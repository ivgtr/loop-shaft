# Mining, discovery and logistics balance

この文書は2026-09-22のゲームバランス改修の仕様です。旧UI改修での「価格・解放順を変更しない」はその作業範囲の制約であり、今回の数値調整には適用しません。数値の実体は `src/game/config.ts`、ドロップ規則は `src/game/mining.ts`、発送規則は `src/game/dispatch.ts` に置きます。

## 採用する構造

通常鉱脈の安定生産を残し、その横に自分で取りに行く発見を置きます。同所に滞在することを罰したり、全地点の利用率を均等にしたりする設計ではありません。

- 通常鉱石は再生する。連続採掘で通常収量・通常抽選率を下げない。自動化した仕事を任せ続けられる。
- 目視できる濃集部は通常報酬への有限の上乗せ。採掘何回後に何が出るかを事前表示し、掘り切ったら通常生産に戻る。時間切れや短時間の再出現はない。
- 鉱石・化石・遺物・研究・Coreは、誰が採っても物理貨物として発生し、地上の鑑定まで通貨・Data・Coreにしない。
- 装備で採算や操作負担が変わり、採掘員・運搬員・Railを導入すると実際の運搬経路が変わる。

## D-001の役割

| 地点 | 役割 | 固有の意味 |
| --- | --- | --- |
| Scrap Ledge | 小口の初期収入 | 柔らかい岩から初期バッグに収まる鉄を得る。配置を作業台に重ねず、短い往復で不足額を作る。 |
| Copper Pocket | 設備投資後の量産 | 4～6個の鉱石。初期バッグでは残ることがあるが、Frame Packなら通常一回分を運べる。硬さ・移動・容量をまとめて評価する。2回目には金の濃集部がある。 |
| Fossil Crack | 任意の発見 | 通常鉱石は少ない。初回Trilobite、3回目Ammoniteを保証し、通常抽選も化石中心。Scrap効率だけで遠方を上位互換にしない。 |

地点の役割、残る濃集部、Core残量をCanvasの状態欄と対応する読み上げ情報に表示します。詳細にはワールド座標と実際の移動速度から求めた往復歩行時間と平均通常鉱石重量を出します。これはリフト待ち・荷詰め・抽選を含まない目安であり、実測収益とは区別します。

## 通常抽選と発見

`rollMiningLoot` をPlayer・Miner・Boreで共有します。場所とSeedが同じなら、採掘担当を変えても通常抽選・発見保証・有限残量の規則は変わりません。担当IDはイベントと貨物の由来としてのみ付与します。

通常鉱石の構成には地点別の重みを使います。特殊品はカテゴリを抽選した後、種類の重みと深度条件で選びます。例えばD-001の通常抽選からDeep Gemを出しません。見えている濃集部は別の保証報酬であり、意図的な先取り発見を許します。

濃集部の内容はFloor Seed・地点ID・採掘回数から決まり、プレビューは乱数を消費しません。初化石・初遺物・初研究の救済判定は「生成された発見」を記録します。未輸送だから、またはDataを使い切ったからという理由で初回保証を何度も発動させません。

D-180の各地点は最初の破壊で装備箱を保証します。以後の装備抽選も残し、Ruined Workshop / Archive Vault / Sealed Chamberの部位傾向を維持します。D-250のHanging Veinにも初回の深層装備を置きます。

## 購入と深度進行

初期価格はTool 90、Boots 160、Auto Swing 180、Pack 240、Porter 550、Auto Dispatch 900 Scrapです。

Tool / Boots / Packに一本道の前提は設けません。Auto Swingは手動6振り、Porterは物理納品1回、Auto Dispatchは地上発送1回を経験してから購入できます。購入ガイドは推奨順であり、必須順ではありません。

D-030は最初の地上納品後、1200 Scrapで開通できます。PorterとAuto Dispatchは必須にしません。Shaft Blueprintの70%割引は維持します。D-060は3600、D-100は5000、D-180は11000 Scrap。研究・発見・物流の前提はそれぞれ残します。

開通と移動は別操作です。開通費用は一度だけ払い、貨物を失わずに移動できる条件を維持します。運搬を終わらせるために停止することはあっても、荷物の所持だけで歩行・採掘を禁止しません。

## 発送方針

| 方針 | 通常の重量目標 | 重要貨物の待ち上限 | 全貨物の待ち上限 |
| --- | ---: | ---: | ---: |
| BALANCED | 容量の60% | 4秒 | 15秒 |
| BULK | 容量の85% | 24秒 | 24秒 |
| PRIORITY | 容量の55% | 1.5秒 | 8秒 |

重要貨物はResearch・Core・Relic・装備箱です。発送が可能な状態で、重量目標・待ち上限・積めない運搬者のいずれかを満たせば出発します。待ち上限は「発送できるまで」の値であり、地上への到着時間ではありません。積載動作中・別ルート運行中の物理制約は迂回しません。

時計は最初に積んだ貨物を基準にし、追加入荷・方針変更・自動発送のOFF/ON・セーブ復元でリセットしません。空荷と出発後にはリセットします。Elevator Rhythmが有効なBALANCED/BULKは85%を目標としますが、重要貨物と最大待ち時間の条件も残します。

## 有限CoreとReboot

Coreは生成時点でその地点の残量から引きます。床・バッグ・リフトに置いたまま再採掘しても補充されません。

| 地点群 | 一周のCore上限 |
| --- | ---: |
| D-100 Core Shell | 4（最初2、その後1ずつ） |
| D-180 Workshop / Archive / Chamber | 1 / 1 / 4 |
| D-250 Hanging Vein / Terminal | 2 / 3 |
| D-400 Edge / Echo / Fracture | 1 / 2 / 4 |
| D-650 Boundary | 2 |

Core Shellの濃縮層を掘り切っても通常鉱石は採れます。深層のCoreは残量がある間、6回の採掘ごとに少なくとも1単位を保証し、不運だけで延々と止まらないようにします。Core Matrixが残量を超える場合はFragmentにします。

Rebootで新しい周回の残量を生成します。最初の2CoreでRebootするか、残りも掘ってから戻るかを選べます。Rail / Freight / Boreなど深層の恒久Protocolには対応する深度の到達記録も要求し、D-100だけを反復して全深層設備を先取りする経路を防ぎます。既に購入済みのProtocolは失わせません。

## 成長・自動化

Last Swingはダメージを与えた後に残るHPが `min(最大HPの15%, 今回ダメージの75%)` 以下なら、その端数を掘り切ります。既に致死量の攻撃を派手にするだけでなく、実際の振り数を減らします。Player・Miner・Boreで同じ規則です。

Anomalyは用途を分けます。Gold Rushは通常量を減らし高価値品を狙う、Heavy Worldは移動を遅くする代わりに査定額を増やす、Empty Shaftは小容量高速便、Living Rockは供給を増やす代わりに運搬能力が重要、Fragile Realityは壊しやすさと通常量を交換します。優劣がないと断言せず、採掘・運搬・発送のどこが詰まるかで評価します。

採掘員のANYはID順ではなく、通常報酬・有限報酬・硬さ・実移動・搬入地点を考慮します。NEARESTは単純な近さ、RESEARCH/RAREは目的別に評価します。Rail設置後は実際の集積先が採算に反映されます。Boreは破壊前に一回分の出力容量を確保し、出たレア品を容量不足で消しません。

## セーブ互換

v6のキーとバージョンを維持し、鉱脈の採掘回数・Core生成済み量、生成済み発見カテゴリ、発送方針・待ち時計を追加します。既存の所持品・床の鉱石・貨物・装備・資産は保持します。

復元時に鉱脈の価格・収量・位置など静的な定義を旧セーブから戻さず、現行の設定を使います。掘りかけHPと再生時間は進捗割合を移します。同じ最大HPの保存・復元でHPが増えないよう、浮動小数点の端数も検証します。

新カウンタのない進行済みv6セーブでは、解放済みフロアの歓迎濃集部は消費済みと扱います。古いCore Shellの破壊回数から消費量を復元します。未解放フロアの新しい濃集部は残します。旧データでは「解放済みだが未訪問」を完全に識別できないため、この一度限りの移行は重複報酬を避ける保守的な扱いです。

## 検証方法

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run test:balance
npm run balance:report
npm run test:e2e
```

`balance:report` は明示実行時だけ `docs/balance-results.json` を更新します。通常のテストではドキュメントを変更しません。レポートには設定のハッシュ、Seed、0.1秒刻みの条件と実際の比較結果を記録します。

収益比較は12 Seed・各360秒。初期装備とTool/Boots/Pack更新済みの状態を別々に測ります。比較の装備は統制条件として与え、購入費は差し引きません。近場固定・銅固定・化石固定・濃集部を探す方針を比較し、別枠でAuto Swing・Porter・Auto Dispatchの固定操業も測ります。

初周試走は6 Seed × 探索先行/自動化先行の12通り。新規セーブの0 Scrapから、通常の購入・採掘・回収・積載・発送・研究・階層移動を通じ、Coreが地上へ届くまでを測ります。開通費を省略したり、採れた品を直接通貨に変えたりしません。

これは反応遅延や迷いのないスクリプトの試走です。最適解の証明、人間の初周所要時間、3時間の面白さを検証済みとはしません。初周45～60分は人間のプレイで調整する仮目標とし、平均だけでなく遅いSeed・ルート・入力負担を見る必要があります。

### 人間が確認する項目

- 最初の10分で、装備による行動変化・発見・一工程の自動化を理解できるか。
- 濃集部の表示から「なぜここへ行くか」を判断でき、消費後も通常収入が減らないと分かるか。
- 近場、量産、発見のいずれも選択として成立するか。遠方を巡回する義務になっていないか。
- 地上への未到着を損失と誤解しないか。自動発送の待ち理由を読めるか。
- Core残量を見てRebootと深層開拓を比較できるか。
- 2周目以降、仕事を任せて別の発見へ行く意味と、旧フロアの操業を維持する意味があるか。

今回、互いに競合する案を全部積みません。隠れた連続採掘ペナルティ、短命のランダム出現を追わせる巡回、地形全体の掘り進み・経路再生成は採用していません。最後の案は探索をさらに主役にする別規模の設計であり、この改修の再生・物流ルールと混在させません。
