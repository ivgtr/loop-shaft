# 発見のピクセル素材と完成条件

## 範囲

PR #16 の有限手掛かり・品質・鑑定・物理物流を描画へ接続する第一段階。D-001 の鉱脈、共通貨物、手掛かりの母岩、リフトの格子扉、Archive の標本を実装する。抽選率、価格、収量、重量、保証、採取所要回数は変更しない。

PR #19の鉱脈・手掛かり・共通貨物・図鑑は維持する。後続では装備部品、受け渡しの位置、設備の建設・稼働・停止を整備する。装備の解放条件・効果、抽選、保存形式は変更しない。深度別背景の新作、全身アニメーションの全面作画、横穴探索は未実施。

### 座標・レイヤー契約

すべて整数ピクセル、アルファ0/255、輪郭もパレット内。拡大はnearest-neighbor、半透明の発光・グラデーション・ランダム粒子を素材へ追加しない。アトラスの行末の未使用セルは透明。

| 対象 | 基準点 | 左右反転 | 前後関係 |
| --- | --- | --- | --- |
| 鉱脈・発見の母岩 | セル(24,40)、D-001では(node.x,node.y+13) | 不可。記憶した露出位置を維持 | 再生鉱脈→有限母岩→作業者。SPENTの穴は不透明な暗色で背後の通常鉱石を隠す |
| 貨物 | セル(6,10)、床・手・各荷台の底面 | 不可。運搬者の向きが変わっても品物の特徴を維持 | 後列→前列。限られた表示枠ではCore・装備箱・未鑑定・Pure等を優先するが、実際の配列・積載順序は変更しない |
| 図鑑 | 24×24を一覧セル中央、上端+11px | 不可 | 標本→名前・件数。未発見は共通母岩。復元の継ぎ目と現物の保存状態を区別 |
| 閉じたリフト | 56×44を既存リフトの描画位置へ | 不可 | リフト背面→実貨物→前枠と格子。貨物の別コピーを扉の前へ描かない |

48×40セルはクリック判定そのものではない。D-001の全鉱脈ピクセルは既存の中心(node.x,node.y+4)・半径22のヒット領域内に収まる。キャラクター、床、貨物のゲーム内座標や当たり判定は変更しない。

### 状態との対応

`src/render/discoveryVisuals.ts` が素材選択の正。母岩は `deriveSemanticRenderState().discoveries` の `signal / stage / remaining` のみを使う。残量0はSPENTの抽出跡で、通常岩のHP・再生時刻によってSEALEDへ戻らない。未公開の手掛かりには母岩を描かない。

貨物は全輸送区間で `drawD001Cargo()` と `cargoSpriteFrame()` を共有する。Normal/Fine/Pureは同じ12×10セルかつ同じ外接範囲内で金属面・輪郭を変え、重量差を示唆する巨大化はしない。集積所・トロッコ・Freight・Bore・Crew貨物も同じ素材を使うが、設備本体には下記の部品素材を重ねる。

未鑑定判定を種類・保存状態・equipmentSeedの参照より先に行う。隠された種類と保存状態を変えても同じセル・同じ表示優先度になる。鑑定直後の既存通知には、実際の `SPECIMEN_APPRAISED` イベントから初めて標本画像を表示する。鑑定結果を先読みして準備する画像用抽選はない。

Archiveには現物の鑑定時に限り `bestSpecimenGrade` を記録する。後から普通の個体が届いてもPristineを失わない。これは収蔵履歴であり、別の採掘状態ではない。v6セーブの任意項目で、古い記録の保存状態は捏造せず通常標本として表示する。復元だけのcount=0記録には現物の保存状態を与えない。後日現物が届いた場合は現物の展示へ変わり、RESTORED履歴は残す。

### 背景との区別

操作対象には連続する輪郭、岩の稜線、地面との隙間を使う。鉄くずは水平に割れる板、銅は硬い外殻と太い鉱床、化石向けは層状の母岩。背景へ同じ露出化石・同じ形の結晶・採掘可能に見える独立岩を飾りとして足さない。照明は現場のランプに限り、発見の常時点滅は使わない。無彩色での差分は機械検査に加え、添付スクリーンショットで確認する。ただしピクセル差の存在は人間の識別率の証明ではない。

## 装備・作業・設備の部品

編集元は `art/d001/work-sprites.json`、生成は `npm run assets:work`。#19と同じパレット・PNG生成器・画像キャッシュを使う。全身×装備組み合わせのアトラスは増やさない。

| 素材 | 接続と重なり |
| --- | --- |
| `work-tools-atlas.png` | 基本工具とFossil / Lightweight / Surveyの先端・柄・付属品。工具だけの待機・構え・打撃セルを既存の体へ合成。回収装備は作業外では背中に固定し、振らない |
| `work-packs-atlas.png` / `work-lamps-atlas.png` | 各3部品を装備ID・affixから選ぶ。バッグ→既存の体・腕→工具→頭部・ランプの順。ランプはポーズの頭位置に追従し、振りかぶった腕の後ろでは隠れる |
| `work-machines-atlas.png` | 支柱・ホッパー・荷台・制御盤・ピストン等を実建設進行から合成。Railの走行・荷役、Freightの位置、BoreのcycleProgress / hitAtで機構を動かす。空仕事・停止中の回転はない |
| `work-porter-rest-atlas.png` | 空荷の回収保留と、荷物を抱えたリフト待ち。既存の2姿勢を修正し、実貨物は別レイヤーで一度だけ描く |

人物の既存素材と装備部品は深い階層でも足基準を合わせて再利用する。深度別景観を新作したという意味ではない。未設置設備は描かず、建設は土台→支柱→機構→制御盤へ進む。満杯のHubは実貨物が棚に積み上がり、荷下ろし待ちのRailは棚の横で傾斜した荷台と閉じた受入口、Boreの出力詰まりは持ち上げた刃と出口の滞貨で表す。ラベルや新しい警告パネルを読ませる方式にはしない。

`cargoMotion.ts`は現在の回収候補・容量・timerから毎フレーム位置を求めるだけで、保存する進捗や貨物コピーを持たない。床→手は床側、手→荷台は手側の一つの現物を移動させ、既存の完了時刻で所有者を切り替える。容量不足分は手元に残し、キャンセル後は実際の所有者へ戻す。競合する回収と積載は完了順を考慮し、同じ現物を二人の手へ描かない。Rail停留所に置いた回収待ち貨物も、中央の平台へ飛ばさず実際の置き場で描く。

床の品質品に追加の常時点滅・浮遊は付けず、#19の輪郭と面を使う。荷台は貨物間の余白を取り、抽出済み母岩と鑑定の素材選択は変更しない。

## 後続に残すこと

通常打撃・破壊・品質上振れ・初発見・鑑定の短い演出は別途整理する。D-030の異常鉱床→D-060の結晶帯→D-100のCore Shellを先行し、D-180 / 250 / 400の景観へ順に進める。地形・構造物を変え、全階層を一度に制作しない。有限の横穴等は人間のプレイを踏まえて選び、新しい抽選を単調さの応急処置として増やさない。

| 出来事 | 時刻の正 | 今回 / 後続 |

将来の短い演出もGameStateへ別の抽選・進捗・残量を追加しない。音を消しても物体から種類を区別できることを条件にする。

## 検証と人間の完成判定

`npm run assets:check` / `npm run typecheck` / `npm test` / `npm run build` / `npm run test:e2e`。

自動検査はアトラスの有効範囲・素材の存在と、保存互換・有限報酬・貨物の所有権・未鑑定情報・装備効果を中心にする。工具・機構の細かな座標、コマ数、正確なバイト数を新たに固定しない。今回の追加は装備の状態参照、受け渡し境界・容量・競合・キャンセル、停止中の非稼働を確認する小さな単体検査に限る。

同じ素材検査を画面サイズとブラウザで複製していたE2Eは一本化する。PCの素材・未鑑定情報・再読込と、390pxのPure鉱石の回収→積載→上昇→換金→再読込を残す。他の操作・保存回帰は件数だけを理由に削らない。PR前に上記コマンドをまとめて実行し、結果をPRへ記載する。

ローカル画像はlocalhostへのブラウザ接続が制限されるため、同じGameRenderer・PNG・ゲーム状態をメモリ上のページへ読み込んで確認する。これはHTTP経由の操作や永続保存の検証ではなく、それらのE2E結果はGitHub Actionsの最終ヘッドを参照する。性能計測は描画経路や物量を変えた際の限定的な確認とし、素材小修正ごとに新しい計測基盤・レポートを増やさない。

人間による完成判定は別に行う。普段はPCと390pxで「狙う→当たり→運搬→鑑定」を確認し、320pxとSafari実機は大きな描画変更やリリース前に確認する。装備の拾得で採掘先や運搬方法を変えるか、手掛かりを掘り切った後も目標があるか、2周目の低位装備・重複品が役立つかを実プレイで見る。自動検査や画像差の存在を、人間の識別性・面白さの証明とは扱わない。
