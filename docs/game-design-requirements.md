## 0. この依頼の前提

現行版は **世界観・画面構成・深度進行のプロトタイプ** としてのみ参照し、ゲームロジックは原則ゼロベースで設計し直してください。

特に、現在のような「画面上のキャラクターやエレベーターがゲーム状態と無関係に常時動き続ける」「ボタンを押すと数値だけ即座に加算され、その結果を画面が後追いで表現する」設計は廃止します。

新しい実装では、

> **プレイヤーの操作 → キャラクターが行動 → 物が採れる → 運ぶ → エレベーターに積む → 地上へ送る → はじめて資源として換金・研究される**

という因果関係を、ゲーム内部のシミュレーションと画面表現の両方で一致させてください。

「数字が増えるUI」ではなく、**地下採掘基地を眺めながら、手作業だった工程が少しずつ機械化・自動化されていくゲーム**を目指します。

# 1. ゲーム概要

## 仮タイトル

**LOOP SHAFT**

## ジャンル

- ブラウザ向けインクリメンタルゲーム
- 採掘 / 物流 / 自動化
- ローグライト的な周回
- 装備更新
- ランダムドロップ / ガチャ的収集
- 軽い拠点運営

## 想定プレイ時間

最初の目標は **1セッション約3時間遊べる密度** とします。

3時間で完全クリアする必要はありません。

理想は、

- 0〜60分：初回 D-100 到達と最初の Reboot（人間の仮目標45〜60分）
- 60〜110分：2周目で自動化を実感し D-180 前後へ
- 110〜170分：3周目で複数キャラ・物流自動化・装備ビルドが成立
- 170〜210分：D-250〜400 付近の深層に挑戦

程度。

D-650 以降は「3時間遊んだ後にも先がある」長期目標として残して構いません。

# 2. 最重要コンセプト

## 2.1 最初は不便でよい

このゲームの成長は単純な `×2` の積み重ねではなく、

> **今まで自分でやっていた面倒な工程が、成長によって消えていく**

ことで実感させます。

例：

1. 自分で鉱脈まで歩く
2. 自分でつるはしを振る
3. 採掘物を拾う
4. 自分でエレベーターまで運ぶ
5. 自分でエレベーターを発送する

↓

- 移動速度アップ
- オートスイング
- 運搬員解放
- トロッコ解放
- エレベーター自動運行
- 採掘員配置
- 採掘ドローン
- 遠隔採掘

と変化させます。

**自動化される前の工程をプレイヤーが一度は経験していること**が重要です。

ただし、不便さは距離・容量・作業時間から生まれるものとします。入力の取りこぼし、連打による採掘キャンセル、強制帰還、荷物を持っているだけで行動不能になる制約を、自動化の報酬として残してはいけません。回収・帰還するタイミングは初期状態からプレイヤーが選びます。

---

## 2.2 世界のアニメーションはゲーム状態に従う

常時それっぽく動かしてはいけません。

例えば、

- 採掘していないキャラはつるはしを振らない
- 荷物を持っていないキャラは運搬モーションをしない
- エレベーターは仕事がなければ停止する
- トロッコは運ぶ物がなければ動かない
- 研究員は研究対象がある時だけ端末を操作する
- ドローンは仕事が発生した時だけ出発する

ようにします。

許可される常時演出は、

- 呼吸・待機モーション
- ランプの微かな揺らぎ
- 水滴
- 粉塵
- 機械の待機ランプ

程度です。

---

## 2.3 画面に見えているものがゲームロジックである

数値上だけ存在する生産施設を極力減らします。

建造物を購入すると、

- 作業員が増える
- 部屋に機械が設置される
- ベルトコンベアが延びる
- トロッコが追加される
- エレベーターが大型化する

など、世界そのものが変化するようにしてください。

# 4. ワールド構造

## 4.1 中央シャフト

中央に縦長のエレベーターシャフトを置きます。

これは単なる背景ではなく、全物流の中心です。

各深度には左右に採掘エリアが存在し、

```text
採掘地点
   ↓
坑道
   ↓
中央エレベーター
   ↓

```

という物流を持ちます。

## 4.2 深度ごとのフロア

- D-250〜399：The Lost
- D-400〜649：Null Strata

のようなバイオームを設定します。

「近い普通の鉱脈」か「時間を使って遠くのレア鉱脈」かを選べるようにします。

# 6. プレイヤーキャラクター

## 6.1 移動

鉱脈をクリックすると、キャラクターがそこまで歩きます。床クリックによる地点指定と、A/D・左右キーを押している間の左右移動も可能にします。タッチ操作には左右の移動ボタンを用意します。

移動中は採掘できません。荷物を持っていても移動・対象変更は可能です。移動入力は、クリック移動・回収・帰還・積載を中断して上書きできます。通常時のEscは現在の指示を中断し、選択パネルを閉じます。ワークショップ表示中のEscはウィンドウだけを閉じ、元の鉱脈選択を維持します。

つまり **距離そのものがプレイ時間のコスト** です。瞬間移動や遠隔回収でこの工程を省略しません。Remote-onlyの鉱脈へ自由移動で侵入することも禁止します。

序盤はこれを明確に体験させます。

## 6.2 手動採掘

キャラクターが採掘範囲へ到着後、

- クリック
- Space
- 採掘ボタン

のいずれかでつるはしを振ります。どの入力経路も同じ採掘要求を使います。

1入力 = 1回のスイングです。同じ鉱脈への再クリックで進行中のスイングをキャンセルしてはいけません。スイング終了・鉱脈への到着の直前150msは、次の一振りだけを予約できます。予約は最大1回、対象・フロア・Runに紐付き、期限切れ・対象変更・中断・フォーカス喪失で破棄します。OSのキーリピートや押しっぱなしでは手動採掘を連続実行しません。手を離しても採掘が続くのはAuto Swing解放後です。

実際のスイング開始時に、

1. キャラがつるはしを構える
2. 振る
3. 岩に当たる
4. 岩HPが減る
5. 火花 / 破片が出る
6. 採掘音が鳴る

という順番を必ず見せます。

資源は入力した瞬間には増やしません。

## 6.3 採掘完了と任意の回収

岩の耐久値が0になると、採掘物が物理オブジェクトとしてその場に落ちます。

例：

- 石
- 銅鉱
- 金鉱
- 結晶
- 化石
- 遺物箱

採掘完了を強制回収・強制帰還へ直結させません。そのまま別の鉱脈へ移動・採掘できます。

キャラクター付近でEまたはPICK UPを押すと、近くの採掘物をバックパック容量内でまとめて拾います。個別の粒をクリックさせたり、毎回確認を求めたりしません。回収完了後はその場で待機し、帰還はプレイヤーが別途判断します。

荷物の所持は採掘・移動を禁止しません。バッグ満杯で禁止されるのは追加回収だけです。入らない素材は床に残し、Porter解放後もプレイヤー自身による回収を残します。

## 6.4 入力とフォーカス

ゲーム画面にフォーカスがある時のみ、移動・採掘・回収・発送のショートカットを扱います。Tabで移ったUIボタンのSpace/Enter操作やテキスト入力を横取りしません。移動キーはkeyup、フォーカス喪失、ウィンドウの非アクティブ化、タブ非表示、タッチのキャンセルで解除します。

Spaceは採掘、Eは近くの回収・積載・設備操作、Fは発送に分離します。Eの実行内容は画面内で明示し、採掘連打を別の行動へ自動的に読み替えてはいけません。

ワークショップを開いたら、押下中の移動と先行採掘入力を解除し、プレイヤーの現在の指示を止めます。所持品・床素材・リフト貨物・鉱脈選択は維持します。ウィンドウ表示中は背後のクリックと移動・採掘・回収・発送入力を遮断し、矢印キーは品目選択、Tabはウィンドウ内のフォーカス移動、Space/Enterは選択した操作の実行に用います。キーリピートやダブルクリックで購入直後に自動化を切り替えません。閉じたらゲーム画面へフォーカスを戻し、手動操作は新しい入力から再開します。リフト・Porter・研究などの自律処理は停止しません。

# 7. 運搬とエレベーター

このシステムをゲームの中心にしてください。

## 7.1 採掘物はその場では資源にならない

採れた鉱石は、

```text
採掘
↓
地面に落ちる
↓
拾う
↓
運搬
↓
エレベーターに積む
↓
地上へ輸送
↓
売却 / 解析
↓
Scrap / Data を獲得
```

という工程を経ます。

## 7.2 エレベーター容量

序盤のエレベーターには積載上限があります。

例：

- Mk.I：20kg
- Mk.II：60kg
- Mk.III：180kg

満杯になるまで待つのか、少量でも発送するか選べます。

## 7.3 手動運搬・積載・発送

帰るタイミングはプレイヤーが選びます。荷物を持ってエレベーター付近へ歩き、EまたはLOADで積載できます。RETURNボタン、または荷物を持った状態でのエレベータークリックは「歩いて戻り、可能なら積む」という明示的な指示です。

回収・積載を中断しても素材を消失・複製させません。積載が完了した時だけ所持品からエレベーターへ移し、容量に入らなかった分は所持品に残します。複数の運搬者が同時に回収・積載しても同じ素材を二重に所有しません。

リフト不在・満載時は強制待機にせず、荷物を持ったまま移動・採掘・別の指示へ切り替えられる状態に戻します。

序盤はプレイヤーがFまたはシャフト脇の常設 `SEND` を押して発送します。鉱脈などの選択を切り替えずに発送できるようにします。

発送中は数秒エレベーターが使えません。その間も別の採掘・移動を続けられます。

## 7.4 自動化

後に、

- 満載時自動発送
- 一定時間で自動発送
- 優先荷物だけ即発送
- 複数フロア巡回
- 貨物専用リフト

を解放します。

# 9. 自動化の解放順

自動化は最初から存在させないでください。

## Stage 0 — 完全手動

プレイヤーが、

- 移動先を決める
- 掘る
- 拾う
- 戻る
- 積む

## Stage 1 — 採掘自動化

`Auto Swing`

プレイヤーは、

満載で自動発送。

## Stage 4 — 採掘員配置

フロアごとにキャラクターを割り当て、放置採掘できます。

## Stage 5 — 物流設備

- トロッコ
- コンベア
- 貨物リフト

## Stage 6 — 深層自動化

複数フロアを自律運用。

プレイヤーの役割は「作業」から「配置・優先順位・ビルド構築」に変わります。

# 10. キャラクターのタスク状態

プレイヤーは最低限以下の状態を持ってください。

```text
IDLE
MOVING_TO_POINT
MOVING_TO_NODE
MINING
COLLECTING
RETURNING
LOADING
```

所持品は行動状態と独立します。MININGには手動入力待ちを含め、RETURNINGは明示的な帰還指示だけで開始します。旧セーブのWAITING_FOR_ELEVATORは荷物を維持してIDLEへ戻し、プレイヤーを強制待機させません。

自動化キャラでは、

```text
FIND_JOB
MOVE
MINE
COLLECT
HAUL
DEPOSIT
REPEAT
```

を実行します。NPCの物流上必要な待機状態はプレイヤーの操作制限とは区別します。

**描画アニメーションは必ず現在stateに対応させます。** 荷物を持った自由移動には運搬歩行を使い、停止した場合も所持品の表示を保ちます。

ランダムで発見。

- 金塊

- 宝石
- 隕石片
- 古代コイン
- 王冠
- 懐中時計

# 12. ガチャ的要素

課金ガチャではありません。

「採掘した時に何が出るかわからない」ランダム報酬として実装します。

## 12.1 Treasure Roll

岩盤を完全破壊した時にレア抽選を行います。

レア度例：

- Common
- Uncommon
- Rare
- Epic
- Relic

# 13. パッシブスキル

特定の遺物・カプセル・研究ログからパッシブを獲得できます。

単なる数値倍率だけでなく、**遊び方を変える能力**を重視します。

例：

### Prospector's Eye
遠距離のレア鉱脈を事前に判別できる。

### Strong Back
運搬量 +50%。

### Long Stride
空荷時のプレイヤー移動速度 +65%。

### Last Swing
攻撃後の残HPが最大HPの15%以下、かつ今回ダメージの75%以下なら、その端数を掘り切る。実際の必要打数を減らす。

### Lucky Pocket
運搬時、低確率でアイテムを1個複製。

### Elevator Rhythm
85%以上を積んで発送すると、その往復の移動速度が65%上がる。BALANCED/BULKはこの積載率を目標にし、待ち上限も維持する。

### Fossil Hunter
化石率アップ。ただし通常鉱石価値低下。

### Deep Focus
同じ鉱脈を掘り続けるほど採掘速度上昇。

# 25. 物流をゲームにする

# 26. オフライン進行

オフライン進行は解放後のみ強くします。

## 初期

オフライン効率 0〜10%。

## Reboot後

Core Protocolで上昇。

最終的に 70〜80%。

オフライン計算では、キャラクターの1歩ずつを再現する必要はありません。

現在の採掘・物流スループットを解析して、

```text
実効生産量 = min(
  採掘能力,
  運搬能力,
  Elevator能力
)
```

から計算してください。


クリック判定と強調枠は描画後の位置を基準にします。D-001の位置補正を描画にだけ適用して、判定が補正前に取り残される実装は禁止します。タッチ操作はホバーに依存させず、押下・解放・キャンセルを扱います。

## Canvas内ワークショップ（UI改修・第一段階）

第一段階は「D-001の初回納品 → 購入効果の確認 → 装備更新 → 採掘復帰」をゲームの表示領域内で完結させます。ワークショップの表示・購入は画面外のContext Actionから取り除き、作業台クリック・近接E・初回購入ガイドから同じウィンドウを開きます。初回の物理ループをマウス／タッチでも完結できるよう、近くの回収／積載操作とSENDもCanvas内に表示します。通常HUD・操作列・深度移動／拡張は次節の第二段階で統合します。研究・配員などの詳細画面は第三段階の共通設備ウィンドウへ統合します。

- つるはし・靴・バッグの装備枠は固定し、購入後も消したり並べ替えたりせず「装備中」を示します。装備と自動化を分け、狭い画面では一品ずつ切り替えます。
- 購入前に現在値と更新後の採掘性能・移動速度・容量を比較し、倍率には適用中の効果を含めます。Auto SwingとPorterは「どの手作業を代行するか」と残る手作業を説明します。
- 前提未達／資源不足でも品目の選択と説明の閲覧は可能にし、実行だけを無効にします。価格と判定は実際の購入処理と共有します。
- 購入は一回の明示操作で実行し、結果・更新後の性能・導入済み状態をその場に残します。既存のキャラクター／設備の状態連動描画へ反映し、飾りだけの作業アニメーションは追加しません。
- 初回納品後は、次の更新と不足Scrapまたは前提を短く案内します。資源が足りたら作業台への入口を強調します。自動でウィンドウを開く・強制移動させる・採掘を禁止する案内にはしません。
- 発掘装備の既存の装備機能を失わせません。全所持品をページ切り替えで選べるようにし、直近8件に制限しません。詳細な発掘装備比較・配員画面再設計は後続段階です。

表示はワールドの480×270座標と、読みやすいUIのCSSピクセル座標を分離します。同じゲーム枠内にCanvas描画を重ね、DPR・リサイズに追従させます。透明なネイティブボタンはキーボード・読み上げ・タッチのために同一レイアウトから生成し、見えるHTMLカードを重ねません。ウィンドウの開閉や購入でゲーム枠の大きさ・位置を変えません。小画面はHUD・操作列のための高さを常時確保し、ウィンドウを開いた時だけゲーム枠を広げません。購入／閉じる／品目操作は44 CSS px以上を確保します。

ウィンドウ・選択品目・一時通知はランタイムのUI状態であり、v6セーブに保存しません。旧セーブに残る作業台選択からウィンドウを勝手に再開しません。価格・移動速度・容量・自動化の解放順・物流ルールは変更しません。

受入確認は、購入前後の比較、同じ装備枠の維持、二重購入防止、ウィンドウへのフォーカス制限、背後クリック遮断、押下中入力の解除、閉じた直後の採掘、物理納品前には購入資金が増えないこと、保存後の復元、および320px／390px／デスクトップ表示での枠・判定位置を含めます。主観的な購入体験や進行テンポは人間のプレイ確認を別途必要とします。


## Canvas内の通常操作・リフト（UI改修・第二段階）

通常の採掘・任意回収・帰還・発送・装備購入・階層移動／開通を、画面外の操作列を使わずに行えるようにします。見えるHUDと操作はCanvasに描画し、第一段階と同じ座標から透明なネイティブボタン・読み上げ用情報を生成します。

- 資源と深度／Runは上端、バッグ容量は固定操作部の一箇所、積載量と運行状態はシャフトのSEND付近にまとめます。未導入のEngineer・Freightなどの状態を深度だけを理由に常時表示しません。対象のHP・操作不能理由は短い状態欄に集約し、詳しい操作は「?」で確認できます。
- 移動・MINE・現在のEアクション・RETURN・STOP・LIFT・ヘルプは位置が変わらない操作部にまとめます。320px／390pxでは二段に配置し、各ボタンに44 CSS px以上を確保します。方向ボタンは押下中のみ移動し、解放・キャンセル・フォーカス喪失で解除します。
- リフトはSHIP／TRAVEL／EXTENDの三つに分けます。SHIPは物理発送と自動発送・貨物優先度、TRAVELは接続済みの行き先、EXTENDは開通費用・前提条件と建設を扱います。現在地や開通済み項目は残し、状態を明示します。
- 開通によって自動では移動しません。D-650は既存のEngineer建設を開始し、所定の作業完了までは移動先に現れません。費用・条件・発送／移動可否は既存シミュレーションと共通にし、UI側だけで許可しません。
- 荷物を持った状態、積載中、発送中、研究未完了、資源不足などの理由を表示します。実行できない行き先でも選択して理由を読めます。全接続先へページ切り替えと矢印キーで到達でき、選択とフォーカスを一致させます。
- 空のリフトのクリック・付近でE・固定LIFTボタンは同じウィンドウを開きます。荷物を持ってリフトをクリックした時の帰還／積載指示は維持します。SENDでは選択鉱脈を変えません。
- ウィンドウを開いたら手動移動・先行採掘入力を解除し、背後の移動／採掘／回収／発送を遮断します。Tabをウィンドウ内に限定し、Esc／閉じるで元の鉱脈とCanvasフォーカスへ戻ります。自動物流・研究は継続し、ウィンドウ状態は保存しません。
- 同じ表示サイズであればD-001から別の階層へ移ってもワールドの幅・倍率・位置を変えません。小画面の説明は短縮・ページ分割し、世界座標と一緒に操作文字やタッチ領域を縮めません。

研究・Anomaly・Collection・Core／Reboot・配員・Rail／Freight／Boreの詳細画面は次節の第三段階で統合し、世界内設備の入口と機能を維持します。第二段階の検証には、初回物理納品と購入の回帰確認、発送中のウィンドウ継続、開通後の明示的な移動、入力遮断、全行き先の選択、小画面の判定領域・重なり・階層間の固定表示を含めます。

## Canvas内の設備管理（UI改修・第三段階）

見えるゲーム内UIはCanvas描画に統一し、画面外のContextPanel・管理ボタン列を廃止します。世界内の作業台・分析端末・配員盤・Archive・Scanner・Core・物流設備から対応する画面を開きます。小画面やキーボードでも設備を探せるよう、常設のBASEから現在利用できる設備に同じ操作でアクセスできます。ScannerとRebootは元の設置階層でのみ操作でき、機能の解放条件を迂回しません。

- 共通操作は「分類 → 項目を選ぶ → 詳細を読む → 明示的に実行 → 戻る／閉じる」。ロック中の項目も選択して理由を読め、実行だけを無効化します。長い追加説明・全装備効果はCanvas内で任意に開く詳細に分けます。Rebootの重要な消失条件は実行ボタンと同時に固定表示します。矢印キーは項目移動、PageUp／PageDownは詳細ページ、Tabはウィンドウ内の操作選択です。
- 装備は部位別に全所持インスタンスへアクセスでき、入手順とIDを保持します。現在装備・候補・効果差を表示します。プレイヤーと作業員の比較は実際の装備処理を状態のコピーに適用し、役割や対象鉱脈による差を明記します。他の所有者からの移動は二段階確認し、承認前に所有権を変更しません。
- Researchは実行中／着手可能、計画、完了に分け、費用・所要時間・前提・不足Dataを表示します。完了・購入後も選択中の項目は確認でき、自動進行によって別の実行ボタンへ勝手に置き換わりません。
- 配員盤は作業員を選び、移動先・優先方針・装備を明示的に指定します。方針の巡回ボタンは廃止します。荷物の搬出待ち・移動中は理由を示し、配置先を選んでも作業員を瞬間移動させません。採用・枠拡張・貨物優先度も同じ画面規則に揃えます。
- Collectionの発見履歴・装備発見記録と、パッシブの解放／有効化を区別します。未発見名称・効果は伏せ、2枠のパッシブ上限と解除方法を説明します。
- AnomalyとRebootはまず比較・内容確認を行い、独立した確認状態で実行します。確認画面を開いた直後はキャンセルにフォーカスし、連続クリック・キーリピートで即決しません。Escは確認取消、次のEscで設備画面を閉じます。
- Rebootには実際の獲得Core、引継ぐProtocol／発見／パッシブ、Legacy Lockerが選ぶ実物1件、初期化される資源・未鑑定貨物・設備・配置・階層・残りの装備、次周の開始条件を表示します。未鑑定貨物は獲得Coreへ加えません。報酬や装備所有状態が変わった場合は確認をやり直します。
- Rail／Freight／Boreは建設費用・研究等の前提・Engineer作業・物理バッファ・稼働状態・優先度を表示します。遠隔鉱脈のクリックはBore情報へ接続し、歩いて採掘する操作にしません。
- 設備画面・選択・ページ・確認・通知はランタイムだけに保持します。旧v6セーブの設備選択やReboot確認状態から画面や承認を復元しません。画面を閉じれば元の鉱脈とCanvasフォーカスへ戻り、確認中を含め自動採掘・研究・物流は継続します。開閉時の手動入力解除と背後への入力遮断を維持します。

Canvas描画と透明ネイティブボタンは同一レイアウトを使い、最低44 CSS pxの操作領域を確保します。320px／390pxでも開閉・項目数・階層によりゲーム枠を伸縮させません。価格・解放順・採掘や物流の計算・v6セーブ形式は変更せず、UIの理由説明や比較に必要な既存計算のみ共有します。

## 設備UIの判断・表現（追加レビュー対応）

Canvas統合後の設備UIは、開閉・フォーカス・入力境界を共有し、判断に必要な情報配置は設備別にする。価格、解放条件、物流、v6セーブを変更しない。

- **Reboot／装備移動**: 実行ボタンと同じ画面に獲得・保持・消失、または移動元・移動先・外れる装備を固定表示する。追加説明を開いても要約と実行ボタンは動かさない。Rebootの「KEEP MINING」は何も失わず採掘へ戻る。確認中も結果に影響する変化は再確認する。
- **状態と選択**: 装備中・有効・現在地・現在設定の印は閲覧中の選択枠やキーボードフォーカスと別に表示する。操作不能な項目も調べられる。
- **装備**: 現在装備と候補のピクセルアイコン、変化する実効性能、追加／失う効果を概要へ表示する。変化しない性能や全効果は任意の詳細へ分ける。抽選重みと確率を混同せず、インスタンスIDを通常のプレイ画面に出さない。
- **配員**: 作業員の階層・仕事・優先度を配員盤に並べ、選んだ作業員の設定を同じ画面で操作する。狭く短い画面の名簿はページを分け、全員へアクセスできる。
- **研究・Collection**: 他の候補を調べても実行中研究の進捗が分かる。Collectionは発見物と未発見のシルエットを一覧化し、未発見の名称・効果は隠す。
- **物流**: 路線ごとに入口・トロッコ・ハブ・搬出の流れと詰まり箇所を表示する。優先度は路線の設定候補として選び、明示的な実行で適用する。候補を調べただけで現在設定を変えない。
- **閲覧**: 項目一覧は対象名と件数／表示範囲を明示する。PCは一覧をまとまり単位で切り替える。追加説明は任意に開き、1ページしかなければ説明用の左右ボタンを出さない。実行ボタンの位置は固定する。
- **通知・小画面**: 完了通知は対象・起きた結果を具体的に伝える。縦持ちは安定したviewport高を設備UIに使い、16:9のワールドを伸ばさず開閉でも倍率を変えない。発送スイッチはシャフト脇の制御盤にまとめ、Fキーと直接発送を維持する。

受入確認には、320px／390pxの実描画での不可逆操作の要約、フォーカスと入力遮断、全装備・全作業員へのアクセス、現在設定を変えない優先度閲覧、ページ移動とワールド固定、進捗・詰まりと実状態の一致を含める。自動テストは主観的な操作感や実機Safari検証の代わりにはしない。

# 30. 3時間の進行設計

初周45〜60分を人間の仮目標として一本化します。これは達成済みの主観的プレイ時間ではありません。

| 時間の目安 | 体験 |
| --- | --- |
| 0〜5分 | 完全手動で納品し、初装備と遠方の最初の化石を知る |
| 5〜15分 | D-030の探索を先にするか、運搬・発送を整えるか選ぶ |
| 15〜35分 | Anomaly、発見、D-060の研究で次の目的が変わる |
| 35〜60分 | 有限Coreを地上に届け、追加採掘か初Rebootを選ぶ |
| 60〜110分 | 2周目の序盤短縮、複数作業員、D-180の装備発見 |
| 110〜170分 | 周回と装備を選び、D-250の物流ラインを作る |
| 170分〜 | D-400の遠隔採掘と深層の有限報酬を目指す |

全ての地点を順番に回らせること、毎回同じ装備順を強制すること、長い資金待ちでプレイ時間を稼ぐことを目的にしません。自動化で余裕ができ、新しい発見へ行きたくなることを重視します。

比較は地上到着済みのScrap/Data/Core、初発見・初自動化・初Core納品までの中央値と遅いケース、歩行・入力負担で行います。`npm run balance:report` の決定論的試走を数値の回帰に使い、人間が感じる納得感・退屈さ・3時間の密度は別途プレイ確認します。

# 38. 受け入れ条件

以下を満たすまでは「完成」としません。

## 操作と画面の一致

- 手動のクリック・Space・MINEは同じ一振りを実行し、連打で進行中の振りを消さない
- 先行入力は150ms・最大1回で、対象変更・中断後に残らない
- 岩に当たる前に採掘結果を加算しない
- 岩が壊れるまでLootを生成しない
- LootがElevatorで地上へ到達するまで換金しない
- NPCは実際に仕事をしている時だけ作業アニメーションする
- Elevatorは輸送タスクがある時だけ動く

## 操作の連続性

- 鉱脈を壊した直後、素材を拾わず別の行動を選べる
- 荷物の所持・バッグ満杯でも移動と採掘ができる
- リフト不在・満載・一部積載後もプレイヤーを強制待機させない
- 回収・積載の中断、Porterとの競合で素材が消失・複製しない
- 初回の採掘・回収・帰還・積載・発送をキーボードだけで実行できる
- マウス・タッチでも同じ工程を実行でき、ホバーを必須にしない
- Tab・ウィンドウ切替・Esc・pointercancelで移動入力が残らない
- 購入条件の表示と実際の判定が一致する
- 描画位置とクリック判定が一致する

## 成長

30分プレイした時、

- 初期より移動が速い
- 運搬が楽
- 採掘が速い
- レアアイテムを1つ以上見ている

60〜90分プレイした時、

- 少なくとも1工程が完全自動化されている
- Rebootが選択可能
- 装備ビルドの違いを感じられる

2周目では、

- 1周目の序盤を明確に短縮できる

## 視覚

- 建造物購入が世界に反映される
- Equipmentがキャラクター表示に反映される
- 深度によって背景・岩・Lootが明確に変化する
- 世界がUIの背景ではなく、ゲームそのものになっている

# 41. 実装担当への最終指示

UIや機能数から作らないでください。

最初に作るべきものは、

**「キャラクターが歩いて岩へ行き、プレイヤーの入力で1回つるはしを振り、岩が壊れ、鉱石が落ち、それを持って中央エレベーターまで歩き、積み込み、地上へ送り、そこで初めてお金になる」**

という1本の完成した体験です。

この一連が見ていて気持ちよく、操作して意味がある状態になってから、自動化・ガチャ・装備・Research・Rebootを積み上げてください。

**インクリメンタルゲームの数値システムを作るのではなく、プレイヤーが経験した仕事が、成長によって機械へ委譲されていくゲームを作ること。**
