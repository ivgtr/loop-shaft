# 発見の描画仕様

PR #16 の品質・標本・有限探索を、ゲームの状態に一致するドット絵で表示する。抽選率、保証回数、購入費、容量、所要時間、所有権、セーブ v6 は変更しない。

## 手掛かり

`deriveSemanticRenderState().discoveries` の `signal / stage / remaining` だけで画像を選ぶ。金属片、化石の渦、結晶層に各4フレームを用意する。

| 公開された状態 | 画像 |
| --- | --- |
| まだ手掛かりがない | 描かない |
| SEALED | 母岩に埋まった一部 |
| EXPOSED・残り2作業以上 | 露出した面 |
| EXPOSED・残り1作業 | 抽出直前の全体像 |
| SPENT | 光る素材のない抽出跡 |

画像名の `nearly` は残作業の見た目であり、新しいゲーム状態ではない。通常岩の再生中も痕跡は残る。時間経過や画面再表示による進行・再抽選・再補充はしない。化石の渦はカテゴリ記号であり、埋まっている標本の種類を予告しない。

描画順は鉱脈 → 手掛かり → 作業員・貨物。D-180の専用施設外観も鉱脈の層へ移し、手掛かりや作業員を後から塗り潰さない。

## 貨物

`cargoRenderer.ts` が、床・プレイヤー・初期Porter・Crew・中央リフト・フロア集積所・レール入力・Cargo Hub・トロッコ・Freight・Bore出力で共通の画像を選ぶ。

通常鉱石は丸みのある塊、Fineは一つの尖った稜線、Pureは二つの突起と明るい面。色だけで品質を区別しない。Stone / Iron / Copper に各3フレーム、その他9種、未鑑定標本1種の計19フレーム。鉱石以外に品質ボーナスの見た目を勝手に付けない。

未鑑定標本は必ず同じ母岩＋札。描画の分岐で `specimen` を先に判定し、保存されている種類・保存状態・最終価値を形・色で漏らさない。地上鑑定のタイミングは変更しない。

12×10px、下辺中央を基準に描く。リフト・運搬中は奥から手前の順に重ねる。小さなトロッコやFreightには横に6個の画像を詰めず、実際に所有している先頭最大3個を縦に重ねる。空の設備に見本の荷物を出さない。表示数の制限で所持数・重さは変わらない。

## 採掘演出

実際の `MINER_SWING_HIT` に `depth` を付け、表示中の階層・存在する地点・正のダメージの打撃だけに岩片と短い揺れを出す。D-001は鉱脈と同じ地面補正を使う。全ワールド層と岩片に同じ1pxの揺れを適用し、鑑定通知は揺らさない。

岩片は260ms、揺れは110ms。記録する打撃は最大16件。階層移動・旅行画面・新しいRunで消去する。後続の自動採掘イベントから古い階層の演出を作らない。待機や単なる歩行でつるはしを構えるフォールバックも止め、採掘準備・打撃に限定する。

## 制作・再生成

編集元は `art/discovery/sprites.json`。`.` が透明、他の文字が既存D-001パレットの不透明色。各行がそのまま1pxの並びで、ぼかし・アンチエイリアス・外部画像生成ツールを使わない。

```sh
npm run assets:discovery
npm run assets:discovery:check
npm test
npm run test:e2e
```

Node標準機能だけで2枚のPNGを生成する。PNGはViteのimport経由でビルド内容と一緒に更新される。読込中・失敗時は同じ編集元から一度だけ作った横方向のピクセル列を描く。別の簡略画像や別の状態判定を保守しない。旧D-001貨物アトラスは制作履歴として残すが、ゲーム側のプリロード・選択からは外す。

## 検証範囲

テストは全31フレームのPNGとフォールバックのピクセル一致、パレット・不透明度、秘匿情報、残作業・採取済み状態、再読込、空の所有者、実際の打撃・遠隔打撃・移動時の演出を確認する。ブラウザテストは390/1280px、実際の採掘によるフレーム変化、画像要求の失敗、D-001/D-250/D-400の所有者別描画を含む。所有者別ケースは静止した描画用fixtureであり、その組み合わせがその時点で購入可能である証明ではない。

人間による初周の所要時間・楽しさ、実機タッチ・色覚の確認は別途必要。キャラクター全体の描き直し、深層背景の画像化、隠し通路・地形破壊・工具ごとの操作方式は今回の範囲外。
