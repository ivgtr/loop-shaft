# 報酬演出 第1・第2段階

既存の品質・金品・標本・遺物を、種類の異なる音と現場のピクセル演出で識別する。抽選率・価格・重量・性能・解放条件・鑑定時刻・物流の所有権・v6保存形式は変更しない。

## 音と見た目

| 対象 | 音 | 演出 |
| --- | --- | --- |
| FINE | 小さい単音 | 現場の小さな十字光。横長通知は省く |
| PURE | 澄んだ倍音の三音 | 段差状の結晶面と十字光 |
| 金品 | 低い金属打撃＋不整数倍の倍音 | 横へ跳ねて沈む重い破片 |
| Deep Gem | 高いガラス質の立ち上がり | 鋭い結晶面と外側の光 |
| 未鑑定化石 | 乾いた打撃＋未解決の二音 | 母岩の両側の剥離。種類・品質は隠す |
| 遺物 | 接点音＋立ち上がる低音＋起動音 | 接点が順に点灯 |
| 異常物 | 通常音を引く→低い一打＋硬い高音 | 短い間の後、暗い枠と内向きの線 |
| 初発見／PRISTINE鑑定 | 解決する和音 | 既存の標本スプライトを角飾りで強調 |

すべて輪郭の明瞭なピクセル表現。全面白フラッシュ、画面停止、偽のレア昇格、追加抽選、物理貨物の複製は行わない。第2段階では下記の運搬・鑑定・精算・初使用を接続する。金品のさらに細かい個体別モーションと新規ドロップは対象外。

## 単一の再生判断

`RewardNoticeQueue` の選択結果を描画するときだけ `FeedbackOutput.reward` を呼ぶ。`GameAudio.handle` は報酬を独立に選ばない。同一フレームの低優先度報酬は大きな鑑定へ割り込まず、音だけが先行しない。同じ通知を再描画しても再発音しない。

キュー最大4件、待機8秒で破棄、重複キー履歴128件。350msより古い待機通知には現場エフェクトを再表示せず、表示中の通知と音だけにする。別階層で採掘された通知は現場へ投影しない。地上で確定した鑑定通知は全階層で受け取る。

階層変更・移動・Reboot・Run交換・描画時計の巻き戻り・タブ非表示・Canvas取り外しで古い通知を消去する。音の先行予約も取り消す。ゲームの進行は止めない。

## 公開情報

通常の `DISCOVERY_FOUND.publicKind` は公開済みの鉱物／遺物の種類。未鑑定化石や装備は必ず `SEALED`。演出側は物理貨物の隠し `kind`、標本の `grade`、装備のseedを読まない。鑑定後は既存の `SPECIMEN_APPRAISED` の公開結果を使用する。

## 通常打撃・破壊

通常打撃は命中位置の小さな岩片のみ。実際の `NODE_BREAK` で同フレームの岩片を広くし、プレイヤーの破壊だけ左右1px／110msの画面揺れを付ける。自動採掘の破壊は局所反応に留める。UIと通知は揺らさない。岩片は最大16打撃、260ms。

## 音量と表示設定

既存の `?` ヘルプ画面から、音量0／50／100%、動き（画面揺れと演出移動）、ハイライトをそれぞれ変更できる。設定はゲームセーブと別の `loop-shaft-presentation-v1` に保存する。初期設定はOSの動きを減らす指定を尊重する。ストレージ／AudioContextが利用できなくてもゲームは継続する。

強い報酬時は通常音を短く下げて戻す。報酬声部の先行予約は置き換え時にフェードアウト。通常声部16／全体24の上限と通常作業音の短い同種クールダウンで自動化時の過密を抑える。出力にはコンプレッサーを置く。

## 検証範囲

自動テストは公開情報の境界、状態／乱数の不変、キューの上限・重複・期限、音声の上限・中断、設定保存、ブラウザでの音と表示の同時開始を対象にする。既存の打撃／描画順テストは維持し、打撃と破壊の差だけ更新する。

ブラウザレポートに初鑑定・金品・宝石・遺物・異常物・弱めた演出の画像を添付する。画像差分やAudioContextの稼働確認は、音の聞き心地・音量差・長時間プレイの気持ちよさを保証しない。人間は通常採掘中、複数Crew稼働中、初回標本鑑定の3場面で聴感と強弱を確認する。

## 第2段階：持ち帰った成果を仕事の変化までつなぐ

### 物理貨物の受け渡し

実際に回収／積載できた分だけ `CARGO_TRANSFERRED` を一回発行する。プレイヤー、Porter、Crewの混載貨物は公開済みの見た目から代表音色を選び、発見時と同じ音色の短い断片を鳴らす。未鑑定化石は母岩の音、装備ケースは共通音。中身、保存状態、seed、隠れた価値を音に使わない。同種の自動作業音は第1段階のクールダウン・声部上限に従う。既存の貨物移動アニメーションを維持し、描画専用の物理貨物は作らない。

### 地上鑑定と便単位の精算

中央／Freightが実際に荷下ろしを完了した時、従来どおり資源と鑑定結果を一度だけ確定する。同じ便の公開イベントを `shipmentId` で結び、最後に `SHIPMENT_APPRAISED` を発行する。遅れて処理される装備鑑定にも同じIDを渡す。異なる便の品は混ぜない。

既存の通知キューで、一便につき一つの小さなCanvas鑑定台・精算票を表示する。初発見／高保存状態／新装備など既存の優先度で一品を代表に選び、残りは便の個数と合計へまとめる。代表がない普通便は開封を省く。

- 発見のある便：土払い0〜350ms → 種類350ms → 保存状態／初発見800ms → 普通貨物1550ms → 特別貨物1860ms → 合計2180ms。約3.1秒で閉じる。
- 普通便：精算から始め、約1.8秒で閉じる。
- 土払い中は代表のシルエットを覆う。化石は既存の標本画像で種類を示し、保存状態を示す画像と解決音は800msから。
- 装備鑑定は公開済みの実際のaffix説明を添える。装備操作・比較は既存Workshopを使う。

音は表示開始を起点に同じ時間表で予約する。表示だけのカウントアップであり、資源は開始時に既に使用可能。ゲーム停止、再抽選、偽の昇格、演出終了待ちの加算はない。別の重要報酬や画面切替で中断しても資源は失わず、精算を再実行しない。通知は最大4件／8秒の既存上限を維持し、過密時は古い演出を捨てる。個別の鑑定音と資源獲得音を重ねて再生しない。

### 装備と自動化の初仕事

購入・装備イベントで「これから使うもの」を記憶し、実際の初仕事で接点状の小さなピクセル反応と短い完成音を出す。

| 対象 | 成功を示す実イベント | 表示 |
| --- | --- | --- |
| つるはし | 正のダメージの命中 | 装備名・その命中の実ダメージ |
| バッグ | 実際の貨物回収 | 装備名・現在容量 |
| ランプ | 実際の岩の破壊 | 装備名・最初の調査完了 |
| 靴／Lightweight Pick | 移動中の実座標変化（軽量工具は積載中） | 装備名・現在の実効移動速度 |
| Auto Swing | 自動スイング開始に対応する初命中 | 初自動打撃 |
| Porter／Crew | 初納品／初破壊 | 完了した仕事 |
| Auto Dispatch | 自動発送した便IDの実鑑定 | 初自動便の精算 |
| Rail／Freight／Bore | 初荷下ろし／初鑑定／初物理出力 | 完了した仕事 |

初使用・初稼働の記憶は描画側のセッション内だけに持つ。既存セーブの読込だけでは再生しない。同じ装備の付け直しは繰り返し祝福せず、Reboot／Run交換でリセットする。階層移動やテレポートを靴の使用と数えず、遠隔作業の完了を手前のキャラクターへ投影しない。初使用と希少品が同時なら希少品を先にし、初使用通知は短く待機させる。

### 設定と確認

第1段階の音量・動き・ハイライト設定をそのまま適用する。動きを減らした時は土払いの移動を省くが、種類・状態・精算の情報は段階表示する。全面フラッシュや入力ブロックは追加しない。依存・セーブ形式・抽選・性能・物流時間は変更しない。

追加の自動検証は6件の単体テストと1件のブラウザシナリオ。公開情報境界、実発送からの一回の加算、便の分離、初仕事の判定、音と映像の段階、中断／重複、弱めた演出を確認する。ブラウザレポートには土払い・種類・保存状態・普通貨物・特別貨物・合計・工具初使用の画像を添える。人間の確認は、金品と化石の運搬音の違い、初鑑定の読みやすさ、自動化が混雑した時の耳障りさの3点を優先する。
